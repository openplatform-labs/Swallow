API migration `0034` adds the alternative `rotate-overlap`, with an explicit 1–86400 second grace period. It issues the replacement with a snapshot of the current two permissions and atomically shortens the old token's expiry to the earlier of its existing expiry and the DB clock plus the grace period. The returned `oldValidUntil` and `rotation-audit-v2` show that deadline; it is not extended by a later commit or delivery delay. Both tokens can be used during the overlap, increasing exposure, and their permissions can subsequently change independently. Revoke the old credential explicitly to end overlap early. It returns at most 50 rows for the specified workflow and resource, with a UUID cursor in `next` if `hasMore` is true. UUID order is not time order; separate pages do not form a consistent snapshot and concurrent inserts before the cursor may be missed. Repeat from the start when needed. The response contains actor identities, DB login and reasons, but not template content. It is not a tamper-proof audit or proof of a specific request: audit rows have no request ID, and text lengths cannot identify template values. The separate request lookup described below applies only to version 2 writes. Protect audit data and retention; the index adds storage and insert cost. Docker PostgreSQL and signed JWT tests cover scope, pagination, no direct table access and revocation contention; the Angular browser test verifies display and revoked access with a synthetic JWT. External IdP, operational load/HA and original Novu parity are unverified.

API migration `0053` adds `PUT /v1/experimental/operator/workflow-v2?environmentId=ENV`, accepting the `0051` body with an additional `requestId` UUID, and `GET /v1/experimental/operator/workflow-request?environmentId=ENV&resource=RESOURCE&requestId=UUID`. The trusted API DB login needs EXECUTE on `public.novu_rust_operator_jwt_workflow_write_v2(text,text,text,text,bigint,uuid,text,text,jsonb,jsonb,text)` and `public.novu_rust_operator_jwt_workflow_request_read(text,text,text,text,bigint,text,uuid)`. The same subject, client, environment and resource-specific write grant is required for both, including replay and lookup; a fresh valid token for the same identity can be used. An advisory transaction lock serializes each request ID. Exact replays return `recorded:true,replayed:true`; a changed body under the same ID returns 409. The original workflow update, audit and request record commit or roll back together. Lookup returns the request ID, workflow, resource, reason and creation time without templates or digest. A missing record is not proof of failure while the original transaction may still be running. The protected request table stores an unsalted SHA-256 digest of canonical request content; low-entropy values may be guessed, so restrict access and define retention. Deleting records, asynchronous failover or backup restoration can lose deduplication history; direct DB privileges and old unconditional API paths can bypass it. The original JWT write endpoint and API-key workflow path remain unchanged. The Angular console uses this version for JWT changes and retains uncertain request data in memory for exact retry; it allows request lookup with a fresh token. Docker tests exercise simultaneous identical requests over separate API DB connections, conflicting payload/resource, fresh-token lookup, revocation and audit rollback. Real network loss, external IdP, production HA and original Novu parity remain unverified.

API migration `0054` adds delegated administration of workflow JWT grants. A trusted DB administrator first provisions the operator identity and an exact issuer/subject/client/environment row in `public.novu_rust_operator_jwt_workflow_grant_admins`, choosing `can_read` and `can_write` independently, and grants the trusted API DB login EXECUTE on `public.novu_rust_operator_jwt_workflow_grant_read(text,text,text,text,bigint,text,text,text,text,text)`, `public.novu_rust_operator_jwt_workflow_grant_change(text,text,text,text,bigint,uuid,text,text,text,text,text,boolean,boolean,text)` and `public.novu_rust_operator_jwt_workflow_grant_request(text,text,text,text,bigint,uuid)` as appropriate. The login does not need direct grant or audit table access. Administrators can read one grant with `GET /v1/experimental/operator/workflow-grants?environmentId=ENV&targetIssuer=ISSUER&targetSubject=SUBJECT&targetClientId=CLIENT&resource=RESOURCE&permission=PERMISSION`. Resources `email`, `sms`, `push`, `slack` and `email-provider` support `read` or `write`; resource `audit` supports only `read`. The response reports whether the target identity exists and whether the grant exists.

`PUT /v1/experimental/operator/workflow-grants?environmentId=ENV` requires `requestId`, `targetIssuer`, `targetSubject`, `targetClientId`, `resource`, `permission`, boolean `expected` and `desired`, and a nonempty `reason` of at most 1,000 UTF-8 bytes. The target identity must already exist in the environment. Changes to any identity with the administrator's own issuer and subject are rejected, including a different client ID. The function locks the caller, administrator grant and target identity, compares the existing grant, mutates it and records the actor, DB login, target, reason and previous/current values in `novu_rust_operator_jwt_workflow_grant_audit` atomically. Replays of an exact request return its recorded result, while changed content under the same ID conflicts. `GET /v1/experimental/operator/workflow-grants/request?environmentId=ENV&requestId=UUID` retrieves a committed request for the same JWT identity with current administrator write permission; a missing record does not prove an in-flight request failed. No default administrator grants are created, and this API cannot grant its own administrator access. A delegated administrator can still grant broad access to other identities; protect administrator provisioning, trusted API DB logins, function ownership, schema, audit and request data. Privileged DB edits, identity aliases, shared logins, deletion cascades and restored/asynchronous databases can bypass these controls or lose history. Cross-administrator updates can contend or deadlock; monitor failures and reconcile request IDs. Rejected changes are not audited, and no audit HTTP reader is provided yet. The Angular settings screen can read and change delegated grants and recover requests; see the dashboard README. Docker PostgreSQL and signed JWT tests verify actual recipient access/revocation, audit grants, self restrictions, idempotent concurrency, administrator revocation and audit rollback. External IdP, operational load/HA and Novu parity are unverified.
